# 09 — OneDrive Integration

## 1. The rule

**Nothing is uploaded until the user clicks “Share to OneDrive”.**

Generating the final output writes a file into application storage and nothing
else. There is no scheduled upload, no upload on generation, and no background
job that pushes files. The upload happens on one explicit action and is recorded
against the file.

---

## 2. Flow

```
Verified audit
     │
     ▼
Click "Generate Final Output"
     │  FinalOutputService::generate()
     ▼
Workbook written to storage/app/final-output/
final_outputs row created, onedrive_status = not_uploaded
     │
     ▼
Click "Share to OneDrive"        ← the only point of upload
     │  confirmation dialog
     ▼
onedrive_status = uploading, upload_attempts + 1
     │
     ▼
OneDriveUploader (resolved from config)
     │
     ├─ success ──► onedrive_status = uploaded
     │              onedrive_item_id, onedrive_url, uploaded_at stored
     │              activity log: "Final output shared to OneDrive"
     │
     └─ failure ──► onedrive_status = failed
                    last_error stored and shown
                    Retry offered on the row
                    activity log: "OneDrive upload failed"
```

Sharing an already uploaded file is refused (`422`) rather than silently
repeated.

---

## 3. File naming

```
{SHOP_CODE}_{DEVICE_CODE}_Audit-{NUMBER}_{yyyyMMdd-HHmmss}.xlsx

PHM001_HHT-02_Audit-3_20260825-143349.xlsx
```

Shop, device and audit number appear in the name because the audit number alone
does not identify a count. The timestamp keeps regenerations distinct.

## 4. Destination folder

```
{ONEDRIVE_FOLDER}/{file name}

default:  PharmaVerify/FinalOutput/
```

Set by `ONEDRIVE_FOLDER` and shown read-only on the Settings screen. A
per-shop or per-month sub-folder is an open point — see
`15-ASSUMPTIONS-DEPENDENCIES.md`.

## 5. File contents

| Section | Content |
| --- | --- |
| Header | Shop, device, audit number, audit date, submitted, counted by, record count, generated by, generated on |
| Lines | Product code, barcode, description, batch, expiry, shelf, UOM, price, system quantity, physical quantity, variance, verification status, adjustment status |

## 6. Drivers

`OneDriveUploader` is an interface with two implementations, chosen by
`ONEDRIVE_DRIVER`. The rest of the application never knows which is active.

### `graph` — real Microsoft Graph

Client credentials flow against an Azure app registration.

```
POST https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token
     grant_type=client_credentials
     scope=https://graph.microsoft.com/.default
        ↓  access token
PUT  {root}:/{folder}/{file}:/content            (files ≤ 4 MB)
     or
POST {root}:/{folder}/{file}:/createUploadSession  then PUT in 5 MB chunks
```

`{root}` is `/drives/{drive-id}/root` when `ONEDRIVE_DRIVE_ID` is set, otherwise
`/users/{upn}/drive/root` from `ONEDRIVE_USER_PRINCIPAL`.

### `demo` — demonstration

Copies the file into `storage/app/onedrive-demo/{folder}/` and returns the same
result shape, so progress, success, failure and retry can all be demonstrated
and tested. `ONEDRIVE_DEMO_FAIL_RATE` (0–1) forces a proportion of uploads to
fail so the failure path can be shown deliberately.

The demo driver is active until the client's Azure details are supplied.
Switching is one environment value; no code changes.

## 7. Configuration

```dotenv
ONEDRIVE_DRIVER=graph            # graph | demo

ONEDRIVE_TENANT_ID=YOUR_TENANT_ID
ONEDRIVE_CLIENT_ID=YOUR_CLIENT_ID
ONEDRIVE_CLIENT_SECRET=YOUR_CLIENT_SECRET

# one of the two:
ONEDRIVE_DRIVE_ID=YOUR_DRIVE_ID
ONEDRIVE_USER_PRINCIPAL=stock@yourcompany.com

ONEDRIVE_FOLDER="PharmaVerify/FinalOutput"

# demo driver only
ONEDRIVE_DEMO_FAIL_RATE=0
```

### Azure app registration

1. Azure Portal → **App registrations** → **New registration**.
2. Note the **Directory (tenant) ID** and **Application (client) ID**.
3. **Certificates & secrets** → **New client secret** → copy the value at once.
4. **API permissions** → **Microsoft Graph** → **Application permissions** →
   `Files.ReadWrite.All` → **Grant admin consent**.
5. Put the three values in `.env`, set `ONEDRIVE_DRIVER=graph`, and identify the
   destination drive.
6. `php artisan config:clear`.

Settings → Integrations then reports the driver as `graph` and credentials as
configured. Secrets are never returned by the API or shown in the interface.

## 8. Failure handling

| Cause | Message the user sees |
| --- | --- |
| Not configured | “OneDrive has not been configured yet. Ask your administrator to supply the Microsoft 365 application details.” |
| Sign-in failed | “PharmaVerify could not sign in to Microsoft 365. Please check the OneDrive configuration.” |
| `accessDenied` | “OneDrive refused the upload. The application does not have permission to write to this folder.” |
| `quotaLimitReached` | “The OneDrive account does not have enough space for this file.” |
| `itemNotFound` | “The destination folder could not be found in OneDrive.” |
| Anything else | “The upload to OneDrive could not be completed. Please try again.” |
| File missing locally | “The final output file is no longer available. Please generate it again.” |

Graph responses are never shown raw. The technical detail goes to the log.

### Retry

A failed row keeps its reason in `last_error` and shows a **Retry** button.
Each attempt increments `upload_attempts`, so repeated trouble with one file is
visible. Retry is manual — the application never retries on its own.

---

## 9. Upload history

The Final Output screen is the history: file name, records, verification and
adjustment status, OneDrive status, attempt count, and when it was uploaded.
Filter by `onedrive_status` to find everything still outstanding or failed. The
Activity Log holds the same events attributed to a user.
